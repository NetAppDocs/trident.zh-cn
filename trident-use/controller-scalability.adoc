= 控制器可扩展性
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Trident 通过提高多个存储驱动程序之间的并发性来提升控制器可扩展性。当您启用控制器可扩展性时，Trident 控制器会并行处理存储操作，而不是对其进行序列化，从而在具有大量并发操作的 Kubernetes 环境中提高吞吐量。

默认情况下， `enableConcurrency` 设置为  `false`，并且 Trident 在串行模式下运行。



[[key-concepts-and-definitions]]
== 关键概念和定义



[[controller-scalability]]
=== 控制器可扩展性

控制器可扩展性是指 Trident 控制器并行处理多个存储操作的能力，而不是在单个锁后对其进行序列化。这些操作包括卷创建、删除和调整大小；快照创建和删除；卷发布和取消发布；以及后端管理。

启用控制器可扩展性时，不同卷和后端上的操作会同时进行。这增加了吞吐量，并减少了具有大量并发 PersistentVolumeClaim 和 VolumeSnapshot 操作的环境中的端到端操作时间。



[[default-behavior-serial-mode]]
== 默认行为（串行模式）

默认情况下， `enableConcurrency` 设置为  `false`，并且对于所有新安装和从早期 Trident 版本的升级，Trident 均在串行模式下运行。串行模式无需配置，所有后端和驱动程序在没有额外配置的情况下均可正常运行。除非您明确将  `enableConcurrency` 设置为  `true`，否则运行时行为不会发生更改。



[[controller-scalability-support]]
== 控制器可扩展性支持

以下驱动程序在 Trident 26.10 正式上市时支持控制器可扩展性：

* `asa-r2` (SAN 和 NVMe)
* `ontap-san`
* `ontap-NAS`
* `ontap-nas-economy.`
* `ontap-nas-flexgroup`
* `ontap-san-economy.`
* `google-cloud-netapp-volumes`
* `azure-netapp-files`
* `solidfire-san`


[NOTE]
====
The `google-cloud-netapp-volumes` 和 `google-cloud-netapp-volumes-san`驱动程序不同。Trident 仅支持 `google-cloud-netapp-volumes`。请勿在后端配置或示例中使用 `google-cloud-netapp-volumes-san`。

====


[[how-enableconcurrency-works]]
== enableConcurrency 的工作原理

此 `enableConcurrency`选项是一个全局的、全有或全无的设置。它不能局限于单个驱动程序或后端。当您将其设置为 `true`时，所有后端将同时切换到并发模式。

[IMPORTANT]
====
在启用控制器可扩展性之前，请验证每个后端是否都使用受支持的驱动程序。如果任何后端使用不受支持的驱动程序，Trident 将拒绝启动，并且所有后端的所有存储操作都将失败。启用并发时，Trident 还将拒绝添加使用不受支持的驱动程序的新后端。

====
要识别后端使用的驱动程序，请运行：

[source, console]
----
tridentctl get backends -n trident
----
如果 Trident 因为后端使用了不受支持的驱动程序而拒绝启动，请删除或重新配置该后端，或禁用控制器可扩展性。



[[before-you-enable]]
== 启用之前

在启用控制器可扩展性之前，请确定 Trident 安装中每个后端的驱动程序类型。运行 `tridentctl get backends -n trident`，然后使用下表确定您的环境是否已准备就绪。

[cols="2,1,1,3"]
|===
| 您的后端环境 | 是否可以启用并发？ | 生产就绪？ | 参考 


| 所有后端均使用受支持的驱动程序 (`asa-r2` SAN 和 NVMe， `ontap-san`， `ontap-nas`， `ontap-nas-economy`， `ontap-nas-flexgroup`， `ontap-san-economy`， `google-cloud-netapp-volumes`， `azure-netapp-files`， `solidfire-san`） | 是的。 | 是的。 | 在生产环境中可安全启用。所有受支持的驱动程序都将以并发模式运行。 


| 任何后端都使用不支持的驱动程序 | 否 | 否 | Trident 将拒绝启动，所有后端的所有存储操作都将失败。在启用之前删除或迁移不受支持的后端。 
|===


[[enable-controller-scalability]]
== 启用控制器可扩展性

 `enableConcurrency` 配置选项控制控制器的可扩展性。在 Trident 安装期间或更新现有部署时，必须显式启用此选项。



[[trident-operator-deployment]]
=== Trident 操作员部署

要使用 Trident 运算符启用控制器可扩展性，请在 `TridentOrchestrator`自定义资源 (CR) 中将 `enableConcurrency`设置为 `true`。



==== 新安装

创建或编辑 `TridentOrchestrator` CR 并将 `enableConcurrency`设置为 `true`：

[source, yaml]
----
apiVersion: trident.netapp.io/v1
kind: TridentOrchestrator
metadata:
  name: trident
spec:
  namespace: trident
  enableConcurrency: true
----
应用CR：

[source, console]
----
kubectl apply -f tridentorchestrator_cr.yaml
----


==== 现有安装

修补现有  `TridentOrchestrator` CR 以启用控制器可扩展性：

[source, console]
----
kubectl patch torc trident --type=merge -p '{"spec":{"enableConcurrency":true}}'
----
验证 Trident 是否应用了设置：

[source, console]
----
kubectl get torc trident -o jsonpath='{.status.currentInstallationParams.enableConcurrency}'
----


[[helm-deployment]]
=== Helm 部署

要使用 Helm 启用控制器可扩展性，请将 `enableConcurrency`值设置为 `true`。



==== 新安装

[source, console]
----
helm install trident netapp-trident/trident-operator --namespace trident --create-namespace --set enableConcurrency=true
----


==== 现有安装

[source, console]
----
helm upgrade trident netapp-trident/trident-operator --namespace trident --set enableConcurrency=true
----
或者，在自定义 `values.yaml` 文件中将 `enableConcurrency` 设置为 `true`：

[source, yaml]
----
# values.yaml
enableConcurrency: true
----
然后使用 values 文件安装或升级：

[source, console]
----
helm install trident netapp-trident/trident-operator --namespace trident --create-namespace -f values.yaml
----


[[tridentctl-deployment]]
=== tridentctl 部署

要使用  `tridentctl` 启用控制器可扩展性，请在安装过程中传递  `--enable-concurrency` 标志。



==== 新安装

[source, console]
----
tridentctl install -n trident --enable-concurrency
----


==== 现有安装

要在现有 `tridentctl`部署上启用控制器可扩展性，请卸载 Trident 并使用以下标志重新安装：

[source, console]
----
tridentctl uninstall -n trident
tridentctl install -n trident --enable-concurrency
----


[[verify-that-controller-scalability-is-enabled]]
=== 验证是否已启用控制器可扩展性

启用控制器可扩展性后，验证 Trident 控制器是否在启用并发的情况下运行。检查控制器 Pod 日志：

[source, console]
----
kubectl logs -n trident deploy/trident-controller | grep -i concurrency
----
输出包含一个确认启用并发的日志条目。



[[concurrency-behavior]]
== 并发行为

启用控制器可扩展性后，Trident 控制器将应用以下行为：

* Trident 将单个全局锁替换为细粒度的按资源锁定。
* Trident 对修改同一资源的操作进行序列化，以保持数据一致性。
* 仅从资源读取的操作与该资源上的其他读取操作同时进行。
* Trident 将并发 ONTAP API 请求限制为每个管理 LIF 20 个，以防止后端存储系统过载。
* 如果多个后端共享相同的管理 LIF，则它们共享此 20 个请求的限制。




[[caveats-and-limitations]]
== 注意事项和限制

以下注意事项适用于 Trident 26.10 中的控制器可扩展性：

* 控制器可扩展性仅支持 <<before-you-enable,启用之前>> 中列出的驱动程序。
* Trident 控制器在内部管理并发。此版本不提供用户可配置的并发限制。
* 整体吞吐量取决于正在使用的存储驱动程序、后端响应能力和 Kubernetes API 服务器性能。
* 高并发可能会增加后端存储系统的负载。
* 控制器的可扩展性行为在所有驱动程序中并不相同。
* 由于并行执行，调试并发操作可能会更加复杂。指标和日志可以显示交错操作输出。




[[recommendations]]
== 建议

启用控制器可扩展性之前：

. 运行 `tridentctl get backends -n trident`并记下每个后端的驱动程序类型。
. 确认您的 Trident 版本的受支持驱动程序列表中显示了每个驱动程序。
. 如果任何驱动程序不在受支持的列表中，请停止。在将这些后端删除或迁移到受支持的驱动程序之前，请勿启用并发。
. 启用后，请使用 `kubectl logs -n trident deploy/trident-controller | grep -i concurrency`检查控制器日志。
. 启用后监控后端和 Kubernetes API 服务器性能。
+
** 对于需要高可扩展性的生产环境，请使用正式发布版驱动程序。
** 大规模运行时监控后端和控制器性能。
** 请勿在自动化脚本中假设操作顺序。
